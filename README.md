# WhatsApp Deleted Messages Monitor

Monitors your WhatsApp for deleted messages, saves them, and shows them through a secure web dashboard. When someone deletes a message, you get a WhatsApp notification with the original content and can review everything on the web interface.

## Features

- **Selective monitoring** — only tracks the chats you explicitly add
- Caches every message (text + media) from monitored chats as it arrives
- Detects "delete for everyone" and preserves the original content
- Sends you a WhatsApp notification with the deleted message details
- Web dashboard with a WhatsApp-like messaging interface
- Deleted messages highlighted with red tags
- Media files (images, videos, audio, documents) saved to disk
- Device fingerprinting ([ThumbmarkJS](https://github.com/thumbmarkjs/thumbmarkjs)) + password auth
- Real-time updates via WebSocket
- Dark theme, responsive design

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Frontend | **SolidJS** + TypeScript + Vite |
| Backend | **Hono** on Bun |
| Database | SQLite (bun:sqlite) |
| WhatsApp | whatsapp-web.js |
| Auth | ThumbmarkJS fingerprinting + session cookies |

## Requirements

- [Bun](https://bun.sh) runtime
- Chromium / Chromium-based browser (for whatsapp-web.js)
- (Optional) [PM2](https://pm2.io) for process management
- (Optional) [Caddy](https://caddyserver.com) for HTTPS reverse proxy

## Quick Start

```bash
# Install backend dependencies
bun install

# Build the frontend
bun run build

# Copy and edit the config
cp .env.example .env
# Set AUTH_PASSWORD to something strong

# Run
bun start
```

On first run a QR code appears in the terminal. Scan it with WhatsApp to link the session. After that the session is saved locally.

Open `http://localhost:3000`, log in with your password, go to **Settings** (gear icon), and add the chats you want to monitor.

## Development

Run the backend and frontend dev servers separately:

```bash
# Terminal 1 — backend
bun run dev

# Terminal 2 — frontend (with HMR)
cd web && bun run dev
```

The Vite dev server proxies `/api` and `/ws` to the backend on port 3000.

## Production Deployment

### PM2

```bash
bun run build
pm2 start ecosystem.config.cjs
pm2 save
```

### Caddy

Copy `Caddyfile.example` to `/etc/caddy/Caddyfile`, replace the domain, then:

```bash
sudo systemctl reload caddy
```

Caddy auto-provisions HTTPS. Set `NODE_ENV=production` in `.env` so session cookies are marked `Secure`.

## Configuration

| Variable | Default | Description |
|---|---|---|
| `WEB_PORT` | `3000` | Web server port |
| `AUTH_PASSWORD` | `changeme` | Dashboard login password |
| `NOTIFY_WHATSAPP` | `true` | Send deletion alerts to your own WhatsApp |
| `CHROMIUM_PATH` | `/usr/bin/chromium-browser` | Path to Chromium binary |
| `NODE_ENV` | — | Set to `production` for secure cookies |

## Security

- Password-based login
- ThumbmarkJS device fingerprinting — session tokens validated against fingerprint
- HttpOnly cookies with Secure + SameSite=Strict flags
- Put behind Caddy (or another HTTPS reverse proxy) in production
